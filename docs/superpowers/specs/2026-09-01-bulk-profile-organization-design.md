# 批量整理配置设计

## 目标与范围

在现有多选、批量启动和批量关闭能力上增加非破坏性的批量整理功能，让用户最多两次点击即可对选中配置执行以下操作：

- 移动到指定工作区或设为未分组；
- 收藏或取消收藏；
- 导出选中配置的最小元数据。

第一版不增加批量删除、配置目录复制、浏览数据备份、拖拽排序或新的进程操作。批量导出继续只包含 `browserType` 和 `name`，不包含路径、工作区、收藏、时间、进程记录或浏览数据。

## 用户界面

存在选中配置时，在现有批量启动和关闭操作旁显示“整理选中（N）”按钮。按钮打开一个菜单，包含：

- “移动到工作区”子菜单：全部现有工作区和“未分组”；
- “收藏选中”；
- “取消收藏”；
- “导出选中”。

菜单支持键盘导航、`Escape` 关闭和点击外部关闭。批量任务运行期间，整理菜单以及现有批量启动、关闭入口统一禁用，并显示“处理中…”。页面一次只运行一个批量任务。

操作成功后默认保留仍可见项的选择，便于连续整理。如果移动工作区或取消收藏导致配置不再匹配当前筛选条件，沿用现有隐藏选择清理规则，只取消隐藏项。结果提示使用固定格式汇总“已更新 N 项、未变化 N 项、跳过 N 项”。导出取消保存显示中性提示，不计为失败。

## 模块边界

新增独立的渲染层批量整理模块，负责菜单状态、批量任务协调、结果规范化和中文摘要。`renderer/index.js` 只负责读取当前选择、调用模块和在完成后重新加载配置，避免继续集中业务规则。

主进程提供三个窄接口：

- 批量分配工作区：`{ profileIds, workspaceId }`；
- 批量设置收藏：`{ profileIds, favorite }`；
- 导出指定配置：`{ profileIds }`。

`preload.js` 只暴露对应方法，不向渲染层暴露存储、文件路径或通用 IPC 能力。所有请求在 IPC 边界校验：ID 必须是非空字符串，数组去重后必须包含 1–1000 项，工作区 ID 必须是有效字符串或 `null`，收藏值必须是布尔值。

## 数据一致性

工作区和收藏服务在 `runGlobalMutation` 中读取一次最新配置集合并计算完整结果。存在实际变化时最多调用一次 `setProfiles`；所有目标都未变化或已消失时不写入。不得循环调用现有单项接口，也不得产生逐项存储写入。

目标工作区不存在时整个请求失败且不写入。请求中的已知配置按目标值更新；已经处于目标状态的配置列入 `unchangedIds`；操作开始前已消失的配置列入 `skippedIds`。成功响应为 `{ success: true, updatedIds, unchangedIds, skippedIds }`，三个数组互不重叠。所有有效更新通过一次存储提交原子落盘。存储失败时返回稳定错误码，内存和渲染层均不得提交推测状态。

批量导出由主进程根据当前存储重新解析 ID，并按当前配置列表的稳定顺序生成文档。已消失的目标跳过；没有任何有效目标时不打开保存对话框并返回稳定失败码。成功文档沿用版本 1 格式，只写入选中配置的浏览器类型和名称。

整理和导出不读取或改变浏览器运行状态。运行中、可重试关闭或状态未知的配置均可执行这些非破坏性操作。

## 错误与反馈

主进程只返回可枚举的稳定状态：成功、取消、请求无效、工作区不存在、无有效目标、存储失败或导出失败。原始异常、系统路径和对话框结果不得传入渲染层。

完成后页面重新调用 `getProfiles`，以主进程持久化结果为唯一事实来源，再协调当前筛选和选择状态。请求失败时保留原选择，恢复所有按钮，并显示可重试提示；不得直接修改本地配置对象制造伪成功。

## 测试与验收

服务测试覆盖重复 ID、无变化项、消失项、无效工作区、一次原子写入和写入失败无部分结果。导出测试覆盖最小字段、选中范围、稳定顺序、取消保存、部分目标消失及全部目标失效。

IPC 和 preload 测试覆盖请求形状、1000 项上限、去重、稳定错误码和最小桥接面。渲染层测试覆盖菜单开关、键盘关闭、任务期间禁用、结果摘要、刷新后的选择保留以及隐藏选择清理。

验收时执行完整 `npm test`。进入合并流程前，按仓库发布约束完成本地打包验证；本功能不得改变既有启动、关闭、删除、进程恢复、诊断或导入行为。
