# P0、系统托盘与更新检查重构设计

## 目标与范围

先将主进程、存储、IPC 和渲染状态拆分为清晰模块，再实现单工作区与收藏、排序与最近使用、导入预览、故障诊断、系统托盘和更新检查。继续支持 macOS 与 Windows，保持 CommonJS、原生 HTML/CSS、现有进程安全边界和每批最多四个并发操作，不引入前端框架。

## 模块架构

- `main.js` 仅负责应用启动、窗口生命周期和模块装配。
- `lib/app-store.js` 统一存储访问、默认值、校验和版本迁移。
- `lib/profile-service.js` 处理配置生命周期、收藏、归属和最近使用时间。
- `lib/workspace-service.js` 处理工作区生命周期及批量启动、关闭。
- `lib/import-export-service.js` 处理元数据导入预览、冲突决策和导出。
- `lib/diagnostics-service.js` 返回浏览器、目录和进程的结构化诊断及安全修复建议。
- `lib/tray-manager.js` 管理托盘菜单、窗口显示、运行计数和显式退出。
- `lib/update-checker.js` 执行限频的版本检查并验证远程响应。
- `lib/ipc-handlers.js` 集中注册窄范围 IPC、校验输入并规范错误响应。
- `renderer/profile-state.js` 管理工作区、配置、筛选、排序和选择状态；`renderer/import-preview.js` 管理导入预览交互；`renderer/index.js` 只负责编排和渲染。

重构必须逐模块进行，并持续运行现有测试，避免在同一步同时迁移边界和改变行为。

## 数据模型与迁移

存储增加 `schemaVersion`、`workspaces` 和设置字段。配置以可选字段扩展：`workspaceId`、`favorite`、`lastLaunchedAt`。工作区记录为 `{ id, name, createdAt }`。旧配置默认未分组、未收藏且没有最近使用时间。

迁移由纯函数完成，必须幂等；完整数据校验成功后才写回。删除工作区只解除成员归属，不删除配置、目录或浏览数据。导入导出继续只允许 `browserType` 和配置名称离开应用，不包含工作区、收藏、路径、时间、进程信息或浏览数据。

## 工作区、收藏与排序

主界面增加“全部、收藏、未分组”和自定义工作区入口。用户可以创建、重命名和删除工作区，并从配置卡片设置归属及收藏状态。工作区支持一键启动或关闭，复用现有进度反馈、失败汇总和四操作并发限制。

排序支持名称、创建时间、最近使用和运行状态，选择持久化。成功启动配置后更新 `lastLaunchedAt`；失败启动不更新时间。筛选变化必须移除不可见选择，批量操作只作用于当前可见且选中的配置。

## 导入预览

导入采用两阶段流程。第一阶段只解析、验证并返回“可导入、重复、无效”预览，不写存储或创建目录。用户为重复项选择跳过或自动重命名后，第二阶段才执行导入。

导入期间创建的记录和空目录属于同一批次。任一步失败时回滚本批新增记录，并仅清理本批创建且仍为空的目录。现有配置和目录不得被修改。导入文件上限、名称校验和元数据最小化规则保持不变。

## 故障诊断

配置卡片和诊断面板区分：正常、浏览器路径失效、配置目录缺失、进程状态未知。可用操作包括重新检测、前往浏览器设置和重新创建缺失的空目录。

配置正在运行或进程状态未知时，禁止移动、删除或重建目录。诊断不会自动清除跟踪记录、终止进程或显示未脱敏的系统异常。修复建议使用稳定错误码，渲染层负责中文说明。

## 系统托盘

默认启用“关闭窗口时最小化到托盘”，并允许在设置页关闭。托盘菜单显示运行配置数量，提供打开主界面、启动全部收藏配置和退出管理器。收藏配置按工作区分组显示，未分组收藏项作为独立分组处理。

`isQuitting` 状态区分隐藏窗口和显式退出。关闭到托盘被禁用时，关闭窗口遵循平台惯例；任何会结束管理器的路径都进入相同的退出检查。退出管理器不终止浏览器；存在运行或状态未知的配置时必须明确提醒。取消退出后应用继续驻留，确认退出后移除托盘并正常结束进程管理器自身。

## 更新检查

设置页显示当前版本、启动后检查开关和“立即检查更新”。自动检查在应用启动后异步执行，每 24 小时最多一次，不阻塞窗口创建。手动检查忽略时间缓存，但共享同一进行中的请求。

更新源固定为 `WinterSoHot/browser-multi-instance-manager` 的 GitHub Releases API。响应必须包含高于当前版本的合法语义版本，发布页地址必须使用 HTTPS 且主机为 `github.com`，仓库路径必须完全匹配；只向用户提供“查看下载”，不自动下载或安装。网络超时、限流、无效响应和版本解析失败只产生非阻塞提示，并保留当前应用行为。

## 错误处理与安全边界

服务层返回稳定结果码，IPC 层验证所有标识符、枚举、布尔值和批量大小。渲染层不直接展示本机路径、命令行、PID 或原始系统异常。任意启动参数、完整浏览器数据克隆和包含凭据的导入导出不在范围内。

进程关闭继续遵守现有规则：仅对应用启动的进程树直接终止；恢复的 PID 在发送信号前重新精确验证浏览器可执行文件和配置路径。未知状态只能重试或在警告确认后清除跟踪记录。

## 测试与验收

现有 127 项测试必须保持通过，并新增：

- 存储迁移幂等、旧数据兼容和无效数据拒绝测试。
- 工作区增删改、解除归属、收藏、最近使用和排序测试。
- 工作区批量快照、未知状态处理和四并发上限测试。
- 导入预览、跳过/自动重命名、失败回滚和元数据最小化测试。
- 诊断状态、运行/未知状态修复禁用和错误脱敏测试。
- 托盘隐藏、窗口恢复、运行计数、取消退出和确认退出测试。
- 更新请求限频、单飞、超时、版本比较和 URL 白名单测试。

完成后运行完整 `npm test`、语法检查和本地 `npm run build:mac`，并手动验证工作区、导入预览、诊断、托盘与更新入口。Windows 托盘和安装包由 Actions 验证。只有本地验证通过并明确报告“可以合并”后，获得用户批准才可推送 `main`。
